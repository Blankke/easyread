# 多篇论文同时处理

EasyRead 默认逐篇处理论文，一篇内部仍按现有设置分段并发，其余论文继续排队；问 AI、重译段落等小任务仍使用独立队列

在“设置 → 模型 → 翻译”中的“同时翻译几篇”选择数量，默认 **1 篇**，最多 **4 篇**，修改自动保存，重启 EasyRead 后生效。选择框下方明确提示：多篇并行会叠加每篇的分段并发，可能占用大量内存并触发模型限流，建议保持 1 篇

也可以在数据目录现有的 `config.json` 中设置 `"paper_concurrency": 1` 到 `4`。未设置或值不是整数时使用默认 `1`，手改配置中的越界整数限制在 `1–4`；设置接口拒绝范围外的值。不要覆盖配置中的其他字段

这个值控制论文数；设置中的 `concurrency` 控制每篇内部的分段数，两者会相乘。例如同时 2 篇、每篇 4 段，可能同时调用 8 个模型进程；不会将所有模型调用限制为 2。增加并发会增加瞬时内存和请求压力，不保证所有服务商都能加速

本地调度测试覆盖并行、排队上限和取消；真实账号的限流及多篇同时运行的内存占用尚未实测

本功能及模型 JSON 解析、学术阅读提示词的改进基于 [bisuwuss-netizen 的 PR #64](https://github.com/Edwardxlai/easyread/pull/64)，纳入时保留默认逐篇处理、将上限调整为 4 篇并在设置中明确标注，同时保留顶层块数组兼容
